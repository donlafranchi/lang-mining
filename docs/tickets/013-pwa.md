# Ticket 013: Make it a proper PWA

## Outcome
Install lang-mining to the home screen on iPhone and Android like an app: full screen, its own icon, shortcuts to the deck and quiz, and a clear offline screen instead of a browser error.

## What is already there
A web manifest, 192 and 512 icons, an Apple touch icon and the Apple web-app meta tags. This ticket adds what is missing.

## In scope
- Complete the manifest: id, scope, portrait orientation, category, maskable icon entries, shortcuts to Deck and Quiz, and a description that says Spanish and Farsi
- A service worker (`/sw.js`) that:
  - shows a cached "You are offline" page when a page cannot be loaded
  - caches only the static app files (`/_next/static/` and the icons), never pages, lesson text or API calls
  - never touches anything that is not a same-origin GET
  - updates itself and removes old caches
- An offline page (`/offline`) with a Retry button
- Register the service worker in production only
- Keep `/sw.js`, `/offline` and the icons reachable without the passcode, so the service worker can install and the offline page can load. Nothing private is on them
- Serve `/sw.js` so browsers always check it for updates
- A small install hint: Add to Home Screen steps on iPhone Safari (which has no install prompt), an Install button where the browser offers one. Dismissible, never shown inside the installed app

## Out of scope
- Reading lessons or running the quiz offline (lessons are private, gated and live in the database)
- Push notifications, background sync
- A new icon design (the green "lm" placeholder stays)
- Splash screens for each iPhone size

## Acceptance criteria (pass or fail)
1. The manifest has id, scope, standalone display, portrait orientation, 192 and 512 icons for both any and maskable use, shortcuts to /deck and /quiz, and every icon file exists at the size it claims
2. The passcode gate lets `/sw.js`, `/offline`, `/manifest.webmanifest` and `/icons/*` through, and still gates `/`, `/deck`, `/quiz`, `/sessions/*` and `/api/*`
3. The service worker answers a failed page load with the cached offline page and passes a working page load through without storing it
4. The service worker ignores POST, cross-origin requests and anything under `/api/`
5. Static files are served cache-first and stored, and the cache stays under its size cap
6. A new service worker version deletes caches from older versions
7. Registered in production only, and `/sw.js` is sent with no-cache
8. In a real browser: the service worker registers and takes control, and with the network off a page load shows the offline page
9. No API keys in the repo
